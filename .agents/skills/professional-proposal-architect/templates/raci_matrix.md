# RACI Matrix — Responsibility Assignment Template

> **Purpose:** Eliminate ambiguity in proposal task ownership. Prevent diffusion of responsibility.
> **Golden Rule:** Exactly ONE "A" (Accountable) per task. Zero = inaction. Two = confusion.
> **Timing:** Complete BEFORE the kickoff meeting.

## Role Definitions

| Role | Definition | Communication |
|:-----|:-----------|:-------------|
| **R** — Responsible | Physically executes the work (writers, analysts, designers) | Multiple R's allowed per task |
| **A** — Accountable | Ultimate owner — ensures quality and deadline met | **ONE per task — non-negotiable** |
| **C** — Consulted | Expert input required before finalizing (SMEs, legal, risk) | Two-way communication loop |
| **I** — Informed | Requires visibility but not involved in drafting | One-way (status reports) |

## Variant Frameworks

| Framework | Best For | Key Difference |
|:----------|:---------|:---------------|
| **RACI** | Standard corporate environments | Balanced roles and communication |
| **DACI** | High-velocity startups | Driver replaces Responsible — focuses on rapid decision-making |
| **RASCI** | Complex engineering environments | Adds Support role for hands-on assistance without accountability |

---

## Common Pitfalls

```
❌ Building matrix without defined scope → roles assigned to undefined deliverables
❌ Adding too many stakeholders → paralysis and delayed decisions
❌ Matrix as substitute for communication → it SUPPLEMENTS active team communication
❌ Multiple "A" per task → overlapping authority, no clear owner
❌ No "C" for legal/technical authority → introduces immense risk into final bid
```
